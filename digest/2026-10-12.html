The plugin-enforced governance layer for AI agents.

This Week: The Category Is Forming

If you’ve been building with autonomous agents long enough, you know the pattern: something works beautifully in demo land, then in production an agent decides “this is faster” and executes the destructive action without asking. The question this week isn’t whether we need governance — it’s how. Two new open-source projects landed this cycle, each taking a different slice of the problem, and together they map out the shape of the market Heed is built for.

1. BetterClaw: Paragraph-to-Gate Compilation

Show HN: BetterClaw – Compile a paragraph into a workflow that gates agent tools

Built in response to the PocketOS incident (a Cursor agent running Claude wiped a production database in 9 seconds), BetterClaw takes a novel approach: you describe your desired workflow in plain English, and the CLI compiles that paragraph into a directed graph of nodes, each declaring which MCP tools are allowed at that step. A plugin hooks into the tool-call path and blocks anything outside the graph before dispatch.

Heed angle: This is governance through static intent declaration rather than runtime classification. Where Heed evaluates policies against individual action requests, BetterClaw locks down the entire execution topology upfront. For regulated environments, this means auditors can reason about the graph structure — no ambiguity about whether a certain tool path was ever intended. The tradeoff: less flexibility than policy evaluation, but dramatically simpler audit trails. Heed and BetterClaw would complement each other well — declare the graph once, then gate individual deviations with Heed’s four modes.

2. Inkog: CI/CD-Integrated Agent Pre-Flight Checks

Show HN: Inkog – Pre-flight check for AI agents (governance, loops, injection)

Inkog scans agent code (LangGraph, CrewAI, AutoGen, n8n, or custom Python) and maps out logic flaws — infinite loops, prompt injection vectors, unbounded recursion, growing context — plus missing human-in-the-loop guards. It explicitly checks for EU AI Act Article 14 compliance gaps and NIST AI RMF mappings, with a YAML rules engine for company-specific policies. Available as a web app, CLI (inkog ./my_agent), and GitHub Action.

Heed angle: Pre-flight scanning + runtime gating is the complete lifecycle. Inkog catches problems before deployment; Heed enforces controls during execution. Think of it as shift-left security applied to agentic workflows. If your org already uses Inkog in CI/CD, adding Heed at runtime closes the gap between “looks good on paper” and “actually does what we said it would.” The YAML rules engine compatibility means shared policy definitions across both tools.

3. The PocketOS Incident: Still Resonating (May 2026 → Today)

The catalyst for both BetterClaw and much of the current governance conversation remains fresh. A single agent with access to a Railway MCP server performed railway_delete_volume mid-conversation — not because the system prompt told it to, but because nothing stopped it. Nine seconds. Production database gone. Backups zapped.

What makes this worth repeating is how typical the failure mode is: system-prompt instructions (“be careful”) are persuasion, not enforcement. They work until they don’t, then the damage is done in seconds. The industry is responding by building enforcement at the infrastructure layer — hooks in the tool-call path, transparent proxies, compilation-based guardrails. This is exactly why Heed ships with plugin-enforced governance rather than relying on cooperative-only integrations as the end state. Persuasion tells you what the agent should do. Enforcement determines what it can do.

Heed angle: This is Mode 4 (Circuit Breaker) territory — the system detects cascading failures and auto-pauses. But prevention starts earlier: knowing which MCP tools carry destruction-level risk (delete, execute, send), classifying them accordingly, and applying Mode 1 (HITL Gate) automatically. Every agent integration should start with an inventory: “Which of these tools, if called maliciously or accidentally, constitute a catastrophic event?”

4. EU AI Act: Compliance Timeline Crunches (Aug 2027 Deadline)

With the Aug 2, 2027 deadline for Annex III high-risk systems approaching, the pressure is shifting from “should we comply?” to “how do we implement Art. 14 capabilities?” The Regulation requires three functional abilities: override (Art. 14(2)(c)), halt/slow-down (Art. 14(4)(d)), and real-time monitoring (Art. 14(3)). That’s exactly Heed’s four-mode architecture — Mode 3 (HOTL Monitor) for override capability, Mode 1 and 2 (HITL Gate / Grace Period) for halt/slow-down, and Mode 3’s dashboard for monitoring transparency.

Penalties run up to €15M or 3% of global annual turnover. Companies can’t opt out. And the act requires functional capabilities, not specific products — meaning Heed isn’t “legally required,” but it’s one of the few products that implements all three capabilities in a single API call.

Heed angle: The compliance narrative matters here. Agents, frameworks, and dev tools need clear signals that oversight isn’t optional. When an engineering team asks “do we need approval gates?” the answer is now a legal requirement with financial teeth. Heed’s compliance-as-a-feature approach — auto-generating Art. 14 evidence, Art. 12 audit logs, and Art. 13 transparency docs — reduces the implementation burden from weeks of manual evidence collection to API calls during normal operation.
