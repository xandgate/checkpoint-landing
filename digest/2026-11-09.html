Agentic Ops Digest: Governance Is Going Horizontal

Nov 9, 2026

This Week’s Hook

A pattern is crystallizing across the AI-agent ecosystem: governance is moving from post-hoc audit to pre-execution enforcement. Three separate projects announced on Hacker News this week — Airlock, DashClaw, and a EU AI Act compliance scanner — all target the same problem from different angles. They converge on one insight that Heed has been building toward: you can’t trust an agent to govern itself. The gate has to exist outside the agent loop, and it has to fire before the tool call lands.

Item 1: Airlock – Policy-as-Code for Agent Fleets

An engineer posted Airlock, an open standard for managing autonomous engineering-agent fleets through version-controlled policy files. Key features include OIDC-bound GitHub tokens scoped to role files, per-repository autonomy levels, file-level overrides for sensitive modules (billing, auth), and OTEL-based action telemetry for audits. It even has a shadow mode so orgs can observe behavior before activating controls.

Heed angle: Airlock approaches governance at the orchestrator / CI level — great for fleet-scale consistency. But if an agent escapes the managed pipeline and runs in a personal dev environment, those policies vanish. Heed’s harness-level plugin enforcement plugs that gap by intercepting tool calls at the point of execution, regardless of how the agent got there. Think of Airlock as the guardrail around your CI, and Heed as the seatbelt around every agent session.

Item 2: DashClaw – Interception Before Execution

DashClaw builds on the “stop-before-it-runs” thesis. It inserts between agents and their actions, enforcing YAML-defined guard policies before execution. High-risk tools route automatically for human approval over SSE (with a 10-minute replay window for disconnect resilience). Claude Code integration uses PreToolUse hooks; Node and Python SDKs wrap existing tool calls without framework lock-in. The author is transparent about current limitations: threshold and allowlist rules work well, but contextual reasoning over full conversation history still belongs in a separate eval layer.

Heed angle: DashClaw proves the market signal — multiple builders are converging on pre-execution gates because everyone hit the same wall (“I kept finding out what my agents did after the fact”). Heed’s plugin-enforced architecture goes further by making governance deterministic: critical denylists can reject actions outright without blocking the user, rather than routing everything through a decision queue. The difference matters when an agent fires 200 tool calls per hour and humans aren’t monitoring continuously.

Item 3: EU AI Act Compliance Scanner Finds 97% Non-Compliance

An open-source scanner surfaced findings that approximately 97% of evaluated AI agent implementations fail to meet EU AI Act compliance requirements, targeting the August 2026 enforcement deadline. Art. 71 mandates post-market monitoring for high-risk systems, while Art. 14 requires meaningful human oversight mechanisms. Both provisions are structural: they demand real-time observability and intervention capability, not just documentation.

Heed angle: Compliance isn’t a checklist — it’s an architecture problem. The scanning result makes sense: most agent implementations build functionality first and bolt governance on last (or never). Heed’s approach addresses both Articles directly: Art. 14 human oversight maps onto the reject/approve flow, and Art. 71 post-market monitoring maps onto Heed’s output-stream logging and policy-evaluation audit trail. If you’re planning for the ‘26 deadline, start with instrumented governance, not retroactive documentation.

Item 4: AI Agent Vulnerability & Risk Report

A comprehensive technical report mapped the attack surface introduced by AI agents — prompt injection evolving into workflow manipulation, privilege escalation through tool abuse, and downstream regulatory liability (GDPR exposure from data leaks during unmonitored agent sessions). The report distinguishes prompt injection from SQL injection structurally: where SQL injection manipulates structured query parsers, prompt injection manipulates intent interpretation, making it harder to defend with traditional WAF patterns.

Heed angle: The report’s mitigation recommendation points to “backend immune layers.” That’s exactly what plugin-enforced governance is: a backend filter that doesn’t rely on the LLM self-correcting. When an agent’s prompt gets hijacked, the plugin layer still blocks the dangerous tool call because its decisions are based on static policy + typed tool schemas, not on trusting the model’s judgment. It’s defense against failure, not defense against malice.
